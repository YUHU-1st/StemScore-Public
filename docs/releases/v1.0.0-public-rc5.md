# StemScore 1.0.0-public-rc5

RC5 fixes a large-model resume corruption bug found while downloading MVSep Mega 53 Stems v1 on slow or unstable connections.

- A single `.part` file now has an exclusive inter-process download lock. A second repair task waits for the active writer and reuses the completed file instead of appending concurrently.
- Every retry rechecks the local partial size. A partial larger than the pinned upstream asset is deleted automatically before requesting more data.
- HTTP 416 (Range Not Satisfiable) resets the invalid partial and restarts from byte 0 instead of getting stuck in a retry loop.
- HTTP 206 resume responses must contain a matching `Content-Range` start and pinned total size.
- If a server ignores Range and returns HTTP 200, StemScore overwrites from byte 0 rather than appending the whole object to old partial data.
- A full-size partial is promoted only after SHA-256 verification; a bad full-size partial is deleted and downloaded again.
- Regression tests cover oversized partial recovery, HTTP 416 recovery, invalid Content-Range, and concurrent repair workers.

Validation: 83 automated tests passed.
