# StemScore 可解释性与复现约定

每个处理步骤都有三类证据：输入/输出 SHA-256、实际命令及参数、模型权重与配置 SHA-256。`stemscore-project.json` 保存状态机，`audit/stage-N.json` 保存步骤快照，`logs/stage-N.log` 保存逐行运行日志。

## 处理决策

- 人声/伴奏：优先使用用户自备双输出模型分别预测两轨；其次使用专用人声模型及其互补输出。公开版只有 Mega53 时，单独取 `vocal` 轨并以原混音计算伴奏残差，绝不叠加其它 50 个可能重叠的预测轨。残差在浮点域测量峰值与平均电平，再按同一增益缩放写入 PCM；命令和测量值保存在步骤日志。
- 主唱/和声：Karaoke RoFormer 预测 lead；harmony 是已分离人声减去 lead。这里的“和声”包括叠唱、伴唱和模型无法归为主唱的剩余人声。
- 乐器六分轨：BS-RoFormer SW Fixed 直接输出 bass、drums、other、vocals、guitar、piano；客户端在已分离伴奏上保留五类乐器。权重 SHA-256 固定为 `24e7d35ee9c64415673d3fd33e06a67cac2c103c5df6267ba1576459c775916e`，原权重未声明许可证，因此不随客户端压缩包再分发。
- 去混响角色策略：项目清单的 `settings.dereverb_roles` 保存客户端逐角色选择；默认仅 `lead_vocal`。未选择轨逐字节复制并记录 `bypassed_by_role_policy`，不加载去混响模型。旧项目没有该字段时也采用此默认值。
- 去混响质量门：已选择轨由同一 MelBand-RoFormer 处理；候选平均电平损失超过 6 dB、受保护角色在 6 kHz 以上相对能量损失超过 4 dB，或峰均比下降超过 3 dB 时回退，近静音轨跳过。这些规则只用于防止明显破坏，不声称能证明主观听感。
- 拍速：同时计算默认拍速和 70 BPM 中心的慢速候选；默认候选不低于 130 BPM 且与慢速候选形成误差不超过 8% 的 2:1 关系时，选慢速候选并记录 `half_time_2_to_1`。
- MIDI：钢琴用 TransKun V2；其他有音高单轨用 Basic Pitch 的分角色参数并量化至 1/16；近静音轨输出 0 音符和原因；鼓用 STFT 三频带能量和起音峰值映射到 GM 36/38/42。

## 不夸大的边界

音源分离与自动音乐转写都不是精确逆过程。SHA-256、时长一致和命令重放只能证明流程可复现，不能证明听感正确。模型的 stem 标签也不是音乐学真值：复杂合成音色可能进入 `other`，和声残差可能包含主唱尾音。客户端因此强制每一步人工审查，且从不自动越过审查门。

UVR 的 Demucs v4 `.th` 兼容后端仍保留，但默认乐器流程已经切换到六分轨 BS-RoFormer。不要把来源不明的 `.th` 或 `.ckpt` 文件放入模型目录。

## 重放

1. 保持项目目录、MSST/UVR 模型文件和转写隔离环境不变。
2. 对照 `local-model-inventory.json` 与步骤审计中的模型 SHA-256。
3. 从日志复制命令；命令中的临时目录会变化，但输入文件、配置、权重和推理参数固定。
4. 重放后重新计算产物 SHA-256。GPU 浮点内核可能带来极小数值差异；若要求逐字节相同，应固定 GPU 驱动、PyTorch/CUDA 版本并启用确定性内核，再重新建立基准。
